# API Документация

## Обзор
API для системы управления франшизами с функционалом кошелька, счетов и уведомлений.

## Базовый URL
```
http://localhost:3000/api
```

## Аутентификация
Все защищенные endpoints требуют JWT токен в заголовке:
```
Authorization: Bearer <token>
```

## Endpoints

### Аутентификация (`/auth`)

#### POST `/auth/signup`
Регистрация нового пользователя
```json
{
  "name": "Имя пользователя",
  "email": "user@example.com",
  "password": "password123",
  "role": "user" // или "admin"
}
```

#### POST `/auth/signin`
Вход в систему
```json
{
  "email": "user@example.com",
  "password": "password123"
}
```

### Кошелек (`/wallet`)

#### GET `/wallet`
Получить кошелек пользователя
- **Требует аутентификации**: Да
- **Ответ**: Информация о кошельке и последние 10 транзакций

#### GET `/wallet/transactions`
Получить историю транзакций
- **Требует аутентификации**: Да
- **Параметры**: `page`, `limit`
- **Ответ**: Пагинированный список транзакций

#### POST `/wallet/topup`
Пополнить кошелек (только админ)
- **Требует аутентификации**: Да
- **Требует роль**: admin
- **Тело запроса**:
```json
{
  "userId": 1,
  "amount": 1000,
  "description": "Пополнение от администратора"
}
```

#### GET `/wallet/all`
Получить все кошельки (только админ)
- **Требует аутентификации**: Да
- **Требует роль**: admin
- **Ответ**: Список всех кошельков с информацией о владельцах

### Счета (`/invoices`)

#### POST `/invoices`
Создать счет (только админ)
- **Требует аутентификации**: Да
- **Требует роль**: admin
- **Тело запроса**:
```json
{
  "userId": 1,
  "amount": 500,
  "description": "Счет за услуги",
  "dueDate": "2024-12-31T23:59:59.000Z"
}
```

#### GET `/invoices/my`
Получить счета пользователя
- **Требует аутентификации**: Да
- **Параметры**: `page`, `limit`, `status`
- **Ответ**: Пагинированный список счетов пользователя

#### GET `/invoices/all`
Получить все счета (только админ)
- **Требует аутентификации**: Да
- **Требует роль**: admin
- **Параметры**: `page`, `limit`, `status`, `userId`

#### GET `/invoices/:invoiceId`
Получить детали счета
- **Требует аутентификации**: Да
- **Ответ**: Подробная информация о счете

#### POST `/invoices/:invoiceId/pay`
Оплатить счет
- **Требует аутентификации**: Да
- **Ответ**: Информация об оплате и обновленный баланс кошелька

#### PATCH `/invoices/:invoiceId/cancel`
Отменить счет (только админ)
- **Требует аутентификации**: Да
- **Требует роль**: admin

### Уведомления (`/notifications`)

#### GET `/notifications/my`
Получить уведомления пользователя
- **Требует аутентификации**: Да
- **Параметры**: `page`, `limit`, `isRead`, `type`
- **Ответ**: Пагинированный список уведомлений

#### GET `/notifications/all`
Получить все уведомления (только админ)
- **Требует аутентификации**: Да
- **Требует роль**: admin
- **Параметры**: `page`, `limit`, `userId`, `type`, `isRead`

#### GET `/notifications/unread-count`
Получить количество непрочитанных уведомлений
- **Требует аутентификации**: Да
- **Ответ**: Количество непрочитанных уведомлений

#### PATCH `/notifications/:notificationId/read`
Отметить уведомление как прочитанное
- **Требует аутентификации**: Да

#### PATCH `/notifications/mark-all-read`
Отметить все уведомления как прочитанные
- **Требует аутентификации**: Да

#### DELETE `/notifications/:notificationId`
Удалить уведомление
- **Требует аутентификации**: Да

#### POST `/notifications/broadcast`
Отправить уведомление всем пользователям (только админ)
- **Требует аутентификации**: Да
- **Требует роль**: admin
- **Тело запроса**:
```json
{
  "title": "Заголовок уведомления",
  "message": "Текст уведомления",
  "userType": "all" // или "user", "admin"
}
```

#### POST `/notifications/send`
Отправить уведомление конкретному пользователю (только админ)
- **Требует аутентификации**: Да
- **Требует роль**: admin
- **Тело запроса**:
```json
{
  "userId": 1,
  "title": "Заголовок уведомления",
  "message": "Текст уведомления",
  "sendEmail": false
}
```

## Типы уведомлений

- `invoice_reminder` - Напоминание о счете
- `payment_reminder` - Напоминание об оплате
- `invoice_generated` - Создан новый счет
- `payment_received` - Получен платеж
- `manual` - Ручное уведомление от администратора

## Статусы счетов

- `pending` - Ожидает оплаты
- `paid` - Оплачен
- `overdue` - Просрочен
- `cancelled` - Отменен

## Статусы транзакций

- `pending` - В обработке
- `completed` - Завершена
- `failed` - Неудачная

## Коды ответов

- `200` - Успешный запрос
- `201` - Ресурс создан
- `400` - Неверный запрос
- `401` - Не авторизован
- `403` - Доступ запрещен
- `404` - Ресурс не найден
- `500` - Внутренняя ошибка сервера

## Примеры использования

### Создание и оплата счета

1. Админ создает счет:
```bash
curl -X POST http://localhost:3000/api/invoices \
  -H "Authorization: Bearer <admin_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "userId": 1,
    "amount": 1000,
    "description": "Счет за услуги",
    "dueDate": "2024-12-31T23:59:59.000Z"
  }'
```

2. Пользователь оплачивает счет:
```bash
curl -X POST http://localhost:3000/api/invoices/1/pay \
  -H "Authorization: Bearer <user_token>"
```

3. Получить уведомления:
```bash
curl -X GET http://localhost:3000/api/notifications/my \
  -H "Authorization: Bearer <user_token>"
```

## Email уведомления

Система автоматически отправляет email уведомления при:
- Создании нового счета
- Успешной оплате счета
- Ручной отправке уведомлений администратором

Для работы email уведомлений необходимо настроить переменные окружения:
- `EMAIL_USER` - Email адрес отправителя
- `EMAIL_PASSWORD` - Пароль приложения Gmail
- `CLIENT_URL` - URL клиентского приложения
